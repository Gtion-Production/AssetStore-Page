Troubleshooting

When nothing draws, or the artwork draws wrong.

Nothing draws

WhereCauseFix
uGUI, Shader resolverThe Canvas is missing the additional shader channels.Press Fix Canvas Channels in the inspector. See Canvas Setup.
UI Toolkit, Shader resolverNo URP, Unity older than 6000.3, or the PanelSettings extra vertex channels are not set. A warning is logged.See Shader Setup. Or set the resolver to Automatic, which falls back by itself.
AnywhereThe scripting define Vector_Painter_Enabled is missing, so nothing compiles.Add it in Project Settings › Player.
AnywhereNo document or artboard is set, or the element has no size.Set Source or VPaint Document, an Artboard, and a width and height.

A quick test for the uGUI case: switch the resolver to MeshBatch. It needs no Canvas channels, so if the image appears, a channel is the problem.

Part of the artwork is missing

SymptomCauseFix
Text, a shadow, a glow, a pattern or an image is not drawnThe Shader and MeshBatch resolvers do not draw them.In UI Toolkit use Painter2D (Automatic chooses it by itself). Or draw without them, using Developer mode in the painter so you cannot add them.
Dashes have flat ends, or a radial gradient looks centredThe shader draws dashes with flat ends and ignores the radial focus offset.Use Painter2D for that artwork.

It draws, but looks or behaves differently

SymptomCauseFix
Edges get slightly softer or sharper at times (UI Toolkit)Automatic switched between Painter2D and MeshBatch.Set the resolver by hand.
An animated icon is not drawn from its raster tileA tile is a still image, so the shader draws while an icon animates.Nothing to fix. It is how it works.
A small icon looks slightly different from a large oneAt or below the Raster size a tile is used, above it the shader draws.Lower the Raster size, or turn Raster LOD off for that file in the importer.
An icon does not use its sprite from the Sprite Atlas (uGUI)The atlas rotated the sprite, so it falls back to the vector shader.Turn Allow Rotation off in the Sprite Atlas.
Element opacity or transform does not affect a shader icon (UI Toolkit)Shader icons share one mesh, which does not see each element's own opacity or transform.Put VectorBatchGroup on the thing that moves or fades, or use Painter2D.

Too many draw calls

WhereCauseFix
UI ToolkitIcons under different parents each get their own mesh.Wrap the subtree in a VectorBatchGroup.
uGUIA different material, such as a Mask or a Text, sits between the images in hierarchy order and breaks the batch.Reorder the hierarchy so vector images sit together.
UI Toolkit with Painter2DOne draw call and a gradient slot per element.Use the Shader or MeshBatch for lists and grids.

Which path is drawing?

In UI Toolkit, read usesShader, usesMeshBatchPath and usesSharedBatch on the element. In uGUI, read effectiveResolver and isRasterDrawn on the image. The Resolver comparison explains how each one behaves.

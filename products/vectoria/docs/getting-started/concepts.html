Core Concepts

The ideas the rest of the documentation builds on.

Vectoria has two halves. Vectoria Painter writes .vpaint documents, and Vectoria Image draws them at runtime. These are the terms you will meet in both.

.vpaint document

A .vpaint file is one vector document: layers of shapes, and one or more artboards. It is plain JSON, so it diffs and merges in version control. The artwork stays vector data, so it is crisp at any size, and no per-resolution exports are needed.

When Unity imports the file, the importer prepares it for runtime: shader data and small raster tiles are baked into the asset, so the artwork is ready on the first frame. See Importer.

Artboard

An artboard is a rectangle of the document that you show as one image. A document can hold several artboards (variants of one icon, or a whole icon set in one file). Coordinates are document units, origin top-left, y grows down.

A Vectoria Image shows one artboard of one document. Pick the document first, then the artboard.

Artboard asset type

Each artboard has an Asset Type in the importer that decides what Unity makes from it. For showing artwork with Vectoria Image use UI Vectoria: it keeps the artwork as vector data, with no bitmap and no mesh. The other types (Textured Sprite, Texture 2D, Vector Sprite, UI SVG Image) produce a sprite, texture or mesh for other Unity components. Only UI Vectoria artboards get the import-time baking.

Vectoria Image

The component that draws an artboard: VectoriaImage in uGUI and VectoriaImageElement in UI Toolkit. Both take the same artwork and the same resolvers. They differ in setup: uGUI needs Canvas channels (the inspector has a Fix button), and UI Toolkit needs URP for the shader resolver.

Resolver

A resolver decides how an artboard is drawn at runtime:

  • Shader (GPU): one quad per icon, and the shader draws the outlines per pixel. Crisp at any size, and icons batch into very few draw calls. This is the main path.
  • MeshBatch (CPU mesh, batched): one shared mesh moved by a Burst job. Approximate quality, for many icons where the shader cannot be used.
  • Painter2D (UI Toolkit only): full quality including effects, one pass per element. Best for a few icons.
  • Automatic (the default): uses the Shader whenever it can draw the whole artwork, and falls back to the others when it cannot.

See Choosing a resolver.

Raster LOD and Runtime Raster

Artwork is not always cheapest as vector. Two optional features swap in a bitmap tile from one shared atlas, so tile icons still batch with the rest:

  • Raster LOD: small icons (64 px or less by default) use a tile baked at import, ready on the first frame.
  • Runtime Raster: large, costly artwork is baked once on the GPU at runtime, only where it pays off.

The shader always draws while an icon animates, and until a tile is ready. See Raster LOD, Runtime Raster and How rendering is optimized.
